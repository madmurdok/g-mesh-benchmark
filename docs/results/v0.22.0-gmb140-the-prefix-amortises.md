# GMB-140: the prefix amortises, and the sign flips

**Date:** 2026-08-24
**Run:** `results/session-economy/2026-08-24T17-49-03-418Z.json` — 282 records, 258 `ok`,
24 `skipped`. g-mesh 2.11.0, bench 0.21.0, `claude-sonnet-5`. 3 arms, 2 chains per (corpus, arm),
both corpora. **$20.94.**

**Result:** in a continuing session `gmesh-configured` is **18.2% cheaper** than grep-only baseline,
against **22.8% more expensive** in the isolated-process experiment run the same day on the same
arms and the same corpora. Same tool, same tasks, opposite sign.

## 1. The headline, both ways

| experiment | g-mesh tokens vs baseline | g-mesh turns vs baseline |
|---|---|---|
| `token-economy` (one process per task) | **+22.8%** | −40.7% |
| `session-economy` (one chained session) | **−18.2%** | −45.6% |

Session-economy, paired per task over the 43 tasks where both arms ran and passed:

| arm | tasks | tokens/task | vs baseline | turns/task | vs baseline |
|---|---|---|---|---|---|
| `gmesh-configured` | 43 | 196,853 | **−18.2%** | 3.0 | −45.6% |
| `serena-configured` | 43 | 274,044 | +13.9% | 4.5 | −18.9% |
| `baseline` | 43 | 240,680 | — | 5.6 | — |

Oracle: g-mesh **86/86**, Serena 86/86, baseline 84/86.
Spend: g-mesh **$5.63**, baseline $6.96, Serena $8.35 — g-mesh is the cheapest arm in actual money,
which it was not in token-economy.

## 2. Why the sign flips

The 8,762-token prefix premium is charged **per turn** in an isolated process, because every task
pays it fresh. In a session it is created once and read thereafter, while the thing that grows is
the transcript — and g-mesh's transcript grows more slowly, because it takes 45.6% fewer turns.

Median total tokens by position in the 34-task excalidraw chains:

| position in session | g-mesh | Serena | baseline |
|---|---|---|---|
| 1–5 | 55,381 | 111,011 | **30,826** |
| 6–10 | 133,029 | 146,540 | **80,535** |
| 11–17 | **193,337** | 283,744 | 223,629 |
| 18–25 | 282,940 | 304,337 | **240,062** |
| 26–34 | **344,450** | 445,284 | 419,447 |

Early in a session g-mesh is the expensive arm — it is carrying a prefix baseline does not have and
has not yet saved enough turns to pay for it. Late in a session it is the cheap one.

Cumulatively, on the same chains:

| through task N | g-mesh | baseline | difference |
|---|---|---|---|
| 1 | 44,194 | 26,629 | +66.0% |
| 5 | 388,614 | 226,214 | +71.8% |
| 8 | 750,011 | 422,071 | +77.7% |
| 12 | 1,502,743 | 1,022,686 | +46.9% |
| 15 | 1,996,718 | 2,048,076 | −2.5% |
| 25 | 3,970,940 | 3,809,827 | +4.2% |
| 34 | 6,980,008 | 9,076,652 | **−23.1%** |

**g-mesh goes cumulatively cheaper somewhere around task 12–15** — the first crossing is at task 14,
but the curve wobbles either side of zero between 15 and 30 before separating cleanly. With **two
chains** behind each point, treat the crossover as "roughly a dozen tasks into a session", not as
task 14 exactly.

## 3. What this does and does not license

**It does** mean the token-economy headline should never be quoted as "what g-mesh costs" without
its qualifier. That experiment is the worst case by construction — the README says so — and this run
measures the other end. Both numbers are real; they answer different questions.

**It does not** mean g-mesh is free in a session. For the first ten tasks it is up to 78%
cumulatively more expensive. A short session that asks two or three questions and stops pays the
prefix and never collects.

**Serena does not flip.** It goes +54.5% in isolation to +13.9% in session — the same direction of
movement, since it also carries a prefix, but it never gets below baseline. Its turn saving (−18.9%)
is not large enough to pay for what it carries.

## 4. Caveats that bound this

**`implementation` tasks are absent.** The harness skips `oracle.mode: "test"` tasks in a chained
session — 24 of the 282 records are `skipped` for this reason, including
`tt-implement-release-cancelled-task-bug`, the task GMB-136/138/139 were about. **So this run says
nothing about the post-edit phase**: there are no edits in it. Do not carry the amortisation result
onto that question, or the other way round.

**Cache-creation numbers are not comparable to the token-economy sweep.** This experiment
deliberately does not warm the prompt cache (see `session-economy.ts`'s comment on
`G_MESH_BENCH_WARM_CACHE`) — pre-warming would flatten the very curve §2 is about. Compare totals
and turns across the two experiments; never `cacheCreationTokens`.

**Two chains per (corpus, arm).** Enough for the paired 43-task headline, which averages over both
chains and every task. Not enough for any single position on the curve.

**Category splits are still unusable** from this registry, for the reason established in
`v0.20.0-gmesh-2.8.1-token-economy-findings.md` §3: baseline, an arm no release can affect, lands
outside its own multi-sweep spread in half the categories. Nothing here changes that.
