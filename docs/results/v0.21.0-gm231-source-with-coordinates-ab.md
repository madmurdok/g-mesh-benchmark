Tool sequences, which are what the numbers are about:

```
with    rep1  find_definition
with    rep2  find_definition
with    rep3  find_definition

ctrl    rep1  find_definition
ctrl    rep2  find_definition -> Read      <-- the pattern this task targets
ctrl    rep3  find_definition
```

## What it costs and what it buys

- **Snippet payload: +251 tokens**, paid on every call. (44,164 against 43,913,
  the mean of the two control runs that did *not* read.)
- **Avoided round trip: 22,807 tokens**, paid by the control 1 run in 3.
- **Mean effect: −7,351 tokens, −14.3%.**
- **Break-even: 1.10%.** The snippet pays for itself if the follow-up read
  happens more often than about **once in 91 calls**. Observed here: once in
  three.

The asymmetry is the whole finding. The snippet does not save a turn every
time, because the agent does not always take the follow-up read — but a turn
costs roughly ninety times what the snippet costs, so the expected value is
positive at almost any read frequency above noise.

## The second effect: the variance collapses

Spread across three reps: **11 tokens with, 22,821 without.**

With the source in the response the task is effectively deterministic. Without
it, whether it costs 44k or 67k depends on whether the model decides to open
the file — a decision nothing in the response influences, because the response
gives it coordinates and no code.

That matters beyond this task. A tool whose cost has a bimodal distribution
driven by an agent's discretion is one you cannot budget for, and it is why
guidance text ("once a hit matches, one targeted read confirms it, then stop")
existed at all. Making the read unnecessary removes the discretion rather than
instructing against it.

## A correction, recorded because it nearly changed the decision

An earlier `G_MESH_BENCH_REPS=low` run put the task at 44,173 with GM-231
against GM-236's recorded 43,955, and that was read as a regression — the
change costing ~200 tokens and saving nothing. It was not a regression. The
single control-side data point it was being compared against happened to be one
of the two-turn runs; the 251-token payload cost is real, and it was being
weighed against a lucky sample rather than against a mean.

The harness says this in its own source and it was right: `repetitionCount()`
documents `low` as "for a quick sanity check, not for trusting the resulting
numbers", because v1's single runs "turned out too noisy to trust for
before/after comparisons". At n=1 the structural claims survive (which tools
were called, in what order) and the token numbers do not.

## Scope

`find_references` and the other row-returning tools were deliberately left
alone. Responses are capped at `MAX_RESPONSE_BYTES = 20,000` and pages are cut
to fit, so a source line per row shrinks rows-per-page — buying a snippet at the
price of more pagination, which is more turns, the opposite of the effect
measured above. That half needs its own measurement before it is built.
