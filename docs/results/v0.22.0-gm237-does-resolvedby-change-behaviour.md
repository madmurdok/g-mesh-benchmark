# GM-237: does `resolvedBy` change what the agent does, or just cost tokens?

**Date:** 2026-08-23
**Answer:** No measurable behavioural difference. Recorded as a null result.

**Task:** `ex-default-export-dropdownmenu-group` (excalidraw) — the only bench
task on which rung 4 (`fileName`) fires. One task is a limitation of the
question, not a choice of sample: probing every symbol the corpora's oracles
name gives 24 that resolve by `qualifiedName`, 1 by `fileName`, and 1 that
reaches the semantic rung.
**Arm:** `gmesh-configured` only — `baseline` and `serena-configured` cannot
differ between two g-mesh binaries, so running them would have been pure spend.
**Reps:** 8 per arm (one `normal` run of 3 plus one `max` run of 5).
**Binaries:** `release-2.11.0` against the same tree with `resolvedBy`
suppressed on all four carrying structs *and* the guidance bullet that teaches
it removed — see "The control has two variables" below.
**Machine:** load average 5.96 at the start of the first arm, 10.58 at the
last. Recorded because this session had already produced one worthless
measurement taken at load 155.
**Records:** `results/token-economy/2026-08-23T17-38-12-950Z.json`,
`…T17-50-17-105Z.json` (with); `…T17-43-41-250Z.json`, `…T17-56-44-022Z.json`
(control).

## Result

| | with `resolvedBy` | control |
|---|---|---|
| `find_definition` | 8/8 | 7/8 |
| `Grep -> Read` | 0/8 | 1/8 |
| turns | 2 everywhere | 2, except 3 in the deviant run |
| mean tokens | 44,160 | 46,980 |
| oracle pass | 8/8 | 8/8 |

**In all 15 runs that used the tool, the sequence is identical**: one
`find_definition`, the answer accepted, two turns. Not one re-query by `id`,
not one grep verification, not one early stop. Whatever the field is worth, it
is not visible in what the agent does with a result.

The single deviant control run did not use `find_definition` worse — it did not
use it at all. That is a different phenomenon from the one this task asked
about, and one observation cannot carry it: 0/8 against 1/8 is what an
intrinsic deviation rate of one-in-eight-or-rarer produces routinely.

## The control has two variables, deliberately

The control drops the field **and** the CLAUDE.md bullet that teaches it. That
is the right comparison for "should this ship", since the two ship together —
but it means the deviant run cannot be attributed to the field. That bullet
ends with *"getting candidates back is still cheaper than the tool refusing and
you re-asking another way, which is why they are offered at all"*, which argues
for reaching for the tool at all, not just for reading a field. If anything
moved that run to `Grep`, that sentence is the likelier cause.

## What the field costs

Computed rather than measured, because at this size a measurement is noise:

| rung | bytes | ≈ tokens |
|---|---|---|
| `id` | 18 | 4.5 |
| `qualifiedName` | 29 | 7.2 |
| `name` | 20 | 5.0 |
| `nameAmbiguous` | 29 | 7.2 |
| `fileName` | 24 | 6.0 |
| `semanticNeighbours` | 34 | 8.5 |

Once per response, not once per row: the four anchored tools carry it in
`anchor`. So the ceiling is **8.5 tokens per call**, against roughly 20,000 for
one extra turn. The break-even is about one avoided turn in 2,400 calls.

## Recommendation

**Keep it**, on cost rather than on demonstrated benefit. At 8.5 tokens it
cannot pay for itself in tokens *or* fail to; the argument for keeping it is
that a suggestion presented as a resolution is a correctness problem, and the
field is what distinguishes them in the wire format. That argument was never
about tokens, and this measurement does not weaken it.

What would be wrong is to keep it *believing it improves decisions*. On the one
task where its most interesting rung fires, across eight runs, it does not.

## A flag on GM-231's number

GM-231 reported −14.3% for returning source with coordinates, from a 3-rep A/B
whose control deviated once — `find_definition -> Read`, 66,720 tokens. This
run's control deviated once too, at 66,676 tokens, and the extra five reps then
produced none: 1-in-3 became 1-in-8.

The mechanisms differ (GM-231's deviation was a follow-up *read*, mechanically
tied to the source being absent; this one skipped the tool entirely), so this is
not a refutation. But both numbers rest on a single deviant run in a small
sample on the same task, and the deviation rate is evidently lower than 1-in-3.
GM-231's effect is probably real and its **magnitude is not established**.
Worth re-running at 8 reps before that −14.3% is quoted again.
