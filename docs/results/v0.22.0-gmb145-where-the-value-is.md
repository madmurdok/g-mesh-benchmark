# GMB-145: where g-mesh's value is, and where it is not

**Date:** 2026-08-25
**Status:** synthesis of the 2026-08-24/25 investigation. No new measurement; every number cites the
doc that produced it.

**The short version.** The tool works on the thing it is for, the agent already uses it that way, and
the four attempts to improve it failed because they were aimed at a problem the transcripts do not
show. What decides whether it pays is not the tool — it is how long your session is.

---

## 1. Navigation works, and the agent already trusts it

| | |
|---|---|
| runs opening with a native call | **130 of 140 (93%)** |
| categories at 100% | all except `lookup` (80%) and `control` (89%) — where the guidance doc itself says grep is cheaper |
| `find_references` calls that are the **last** tool call of the run | **60%** |
| median native result size | 3,761 chars; **4 of 229** under 400 |

Source: `v0.22.0-gmb142-how-the-agent-actually-uses-g-mesh.md`, `v0.22.0-gm257-source-in-rows-not-built.md`.

The agent reaches for the index first, gets a substantial answer, and stops on it three times in
five. Fallback-from-failure is not what drives the remaining grep: the index is answering.

## 2. The cost is a prefix, charged per turn

| | |
|---|---|
| static prefix, `gmesh-configured` | **21,705** tokens (86 warm runs, spread 21,178–21,844) |
| static prefix, `baseline` | 12,943 |
| premium | **8,762 per turn** |
| split, by prefix isolation | tool schema +4,662, guidance doc +4,453 |
| cost of a turn, roughly | ~15,100 tokens |

Source: `v0.20.0-gmesh-2.8.1-token-economy-findings.md` §2a, `v0.20.0-guidance-doc-pays-for-itself-findings.md`.

A 3% spread over 86 runs is what makes it *fixed*. It is not a one-off charge — it is re-read on
every turn, which is why cutting turns is worth more than cutting schema bytes, and why the trim
that saved 2,776 tokens a turn was reverted for costing more in turns.

## 3. Which is why the headline's sign is about session shape, not about the tool

Same arms, same corpora, same day:

| experiment | g-mesh vs baseline, tokens | turns |
|---|---|---|
| isolated process per task | **+22.8%** | −40.7% |
| chained session | **−18.2%** | −45.6% |

Source: `v0.22.0-gmb140-the-prefix-amortises.md`.

Per task in a session the two forces are visible separately: the prefix costs **+26,286** (3.0 turns
× 8,762) and the 2.6 turns it saves give back **−111,744**. Net −43,827, which is the −18.2%.

Early in a session the arithmetic runs the other way, because a turn is cheap when the transcript is
short and the fixed prefix dominates it. Cumulatively on the 34-task chains: **+77.7% through task
8, −2.5% through 15, −23.1% through 34.**

### The practical answer

**Roughly a dozen code-navigation questions is where it turns.** Under that, in one continuing
session, you pay the prefix and do not collect. Over it, the turn saving compounds and does not stop.

Two honest qualifiers. Two chains sit behind each point on that curve, and it wobbles either side of
zero between tasks 15 and 30 before separating cleanly — so read it as ten-to-fifteen, not as
fourteen. And a session that compacts or restarts resets the count, because the prefix is paid again
against a fresh transcript.

## 4. Where the headroom is not

On implementation tasks, **67–78% of a run's tokens fall after the first edit** — and `baseline`,
which has no index to abandon, spends **75–77%** there.

Source: `v0.22.0-gmb144-the-ceiling-on-navigation.md`.

So navigation improvements can address at most **22–33%** of those runs, and the phase they cannot
reach is not a behaviour to fix: an arm with no index spends the same share of its run there.
Editing a file and checking what it touched reads files and searches text. That is not navigation.

## 5. Four null results are one finding about method

| attempt | what it did | outcome |
|---|---|---|
| GM-237 | added `resolvedBy` to the response | no change, 15 reps a side |
| GMB-139 | added a post-edit sentence to the guidance doc | target metric unmoved — 1 native call either side |
| GM-256 | disclosed excluded `REFERENCES` on `find_callers` | shipped on correctness; **unmeasurable**, the agent picks `find_references` instead |
| GM-257 | source lines on `find_references` rows | **not built** — the follow-up Read it removes happens in 7% of calls, at +21% payload |

Each was reasoned from what an agent *ought* to need: it ought to want proof the answer is complete,
it ought to want the line of code, it ought to be told when the walk excluded something. The saved
transcripts kept answering with what it *does* — take the index's answer and stop.

The method lesson is cheaper than the four attempts were: **check what the agent currently does
before building the thing that would change it.** Three of these four were killed or de-risked by a
free query against transcripts already on disk. GM-257 cost nothing at all.

## 6. What is worth doing, and what is not

**Not worth doing:** another intervention aimed at making the agent trust the index more. That
premise has been tested four ways and the trust is already there on the tasks where the index is the
job.

**Not worth doing:** trimming the schema tax. GM-188 measured the recoverable prose at ~2% of the
payload; the rest is contract. And the one trim that was tried cost more in turns than it saved in
bytes.

**Worth knowing, not acting on yet:** `find_implementations` and `get_dependencies` are 36% of the
`tools/list` payload for 15 calls across 140 runs (GMB-142 §5). That is the only lopsided
cost-to-use ratio in the surface — but usage follows the registry's task mix, and a tool that is
rarely needed can still be decisive when it is.

**The real remaining lever is not a better index.** It is the two thirds of implementation work that
happens after the edit. Something that made checking a diff's blast radius cheaper would attack it.
That is a different tool, and this benchmark cannot currently measure it either — 3 of 46 tasks have
an edit phase at all.

---

**The conclusion the data supports is that the tool is working as intended on what it is for.** That
is a finish, not a failure, and it is worth writing down precisely because four attempts to find
something else were spent before it was clear.
