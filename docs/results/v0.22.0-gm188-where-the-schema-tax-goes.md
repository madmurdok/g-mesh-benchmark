**Conclusion:** ship nothing. The tax is contract, not boilerplate, and the
recoverable redundancy is ~2% of it. The breakdown is the deliverable.

**Method:** a real `tools/list` response from `g-mesh` at `release-2.11.0`,
captured against a one-file project (9,191 bytes of names, descriptions and
input schemas). Token figures are that byte count apportioned against the
5,543 measured in the 2026-08-14 run — 1.66 bytes per token, which is what

## The split the task asked for

The task's hypothesis was "repeated boilerplate across tool descriptions, and
prose that belongs in the CLAUDE.md snippet". **The measurement contradicts
it.** Tool descriptions are 1,362 B — 15% of the payload. Deleting every one of
them would not close the 2,561-token gap to serena, and they are the trust
contract the task's own non-goal protects.

| | bytes | share | verdict |
|---|---|---|---|
| schema structure (types, names, `required`, enums) | 3,792 | 41% | **cannot be cut** — the protocol's own shape |
| parameter descriptions | 3,920 | 43% | contract, with ~200 B of recoverable repetition |
| tool descriptions | 1,362 | 15% | contract; explicitly out of scope |

**All prose together is 5,282 B — 58% of the payload.** Which means the whole
gap to serena, and more, is prose. There is no version of "trim the fat" that
closes it: closing it means shipping thinner contracts, which is the trade the
task was filed to refuse.

## The redundancy that is real, and why it is not worth taking

1,189 B are literal repeats of five parameter descriptions across tools —
`symbol_name` in 4 tools, `symbol_id` in 4, `file_paths` in 3, `cursor` in 6,
`limit` in 3. **This cannot be deduplicated**: MCP has no include mechanism, so
every tool must carry its own schema in full. It can only be *shortened*, and
shortening it pays 3-6× because it lands in that many tools.

The one genuine wart is `find_implementations`, the most expensive tool at 21%
of the whole tax. Three of its parameters carry the sentence "Ignored when
`transitive: true`", and a fourth carries "Ignored without `transitive: true`":
a cross-parameter interaction matrix written out per parameter. Hoisting it into
the tool description would save ~120 B ≈ **70 tokens, 1.3% of the tax and 2.7%
of the gap**.

That is where this stops. A 70-token saving whose acceptance criteria require a
benchmark re-run of the lookup and ambiguous-name categories to prove the trust
behaviour did not regress is a bad trade: the validation costs more than the
saving returns, forever. Recorded here so the next person does not re-derive it.

## What is actually true about the cost

g-mesh pays ~2.4k more cache-creation tokens than serena because it ships eight
tools whose contracts say what a result guarantees. The README's
"Reducing self-verification cost" measures what that buys: ~38% mean cost drop
on the task it was tested on, from an agent that stops re-verifying results with
grep. The tax is per isolated process; session-economy is where it amortises.

Paying 2.4k tokens once to avoid a 38% ongoing verification cost is not a
problem to be fixed. It is the design working.
