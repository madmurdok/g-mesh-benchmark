Summary

This benchmark compared g-mesh against baseline grep/Read/Glob approaches across 2 code-navigation tasks. Both tools achieved perfect correctness—100% oracle pass rate for each configuration. On token efficiency, g-mesh-configured used 222,853 tokens on average versus 282,389 for baseline, representing a 21.1% unconditional token reduction.

The benchmark included an expected-winner check to see whether prior assumptions about which tool would perform better held up in practice. Of the 2 tasks evaluated, 1 matched the expected prediction while 1 task—ex-semantic-collab-conflict-keep-local—diverged from the expected result.

In aggregate, g-mesh-configured delivered measurable efficiency gains of 21% fewer tokens across paired tasks while maintaining equivalent correctness. The single mismatch between expected and observed performance suggests that task characteristics don't always align with intuition about which approach scales better, indicating value in empirical evaluation on real workloads rather than assumption alone.

For developers deciding between these tools, g-mesh offers a meaningful token reduction without sacrificing accuracy. However, performance improvements appear task-dependent rather than universal, so adoption decisions should consider your specific use cases alongside these aggregate results.
