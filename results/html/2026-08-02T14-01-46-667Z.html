Summary

This benchmark compared g-mesh to traditional code navigation tools (grep, Read, Glob) across 7 representative tasks. G-mesh consumed 7.1% fewer tokens unconditionally, with a 6.6% improvement in paired comparisons across 17 instances. More significantly, g-mesh demonstrated superior accuracy: a 95% oracle pass rate versus 86% for the baseline.

However, important caveats apply. The expected-winner predictions proved unreliable—only 1 of 5 tasks with a declared preference matched observed results. Four tasks expected to favor the baseline or show no difference actually diverged from predictions, including high-fanout reference searches, package dependency incoming analysis, and multiple ambiguous symbol-resolution scenarios.

Token savings are modest, so developers should not expect dramatic cost reductions. The real advantage is accuracy: g-mesh correctly answered roughly 2 additional oracle questions per 21 attempts. Whether adoption makes sense depends on your team's priorities. If correctness in cross-file analysis is paramount and you can tolerate modest token overhead in unpredictable cases, the 9% accuracy improvement may justify the switch. If token efficiency dominates, the baseline remains competitive for many common tasks.
